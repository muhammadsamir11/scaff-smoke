Before we start

You’re ready when the screen is real.

We work from the live product, not a blank brief. Bring the route that feels wrong, the system already in place, and the person who can decide.

What ready looks like

  1. 01

    A live screen

    A production URL, staging build, or Figma frame that already ships. We need hierarchy and contrast in context, not a moodboard.

  2. 02

    The system in use

    Tokens, components, or the folder the team already opens. We extend naming and spacing; we do not invent a parallel visual system.

  3. 03

    One decision-maker

    Someone who can approve type, color, and component changes. Small reviews keep the work proportional to the change.

  4. 04

    A concrete wrongness

    Which screen fails, and how: density, contrast, wrapping, or a component that no longer matches the rest of the product.

What to send

Mail the frame, the route, or the component. Say what should read first and what feels off. We reply with a concrete recommendation before any new visual system.

If you only have a screenshot, send that. If you have access to the codebase, say so — shipped files are part of how we work.
